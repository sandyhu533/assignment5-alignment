# GRPO results summary

Generated by `scripts/summarize_runs.py`. All runs: OLMo-2-0425-1B on GSM8K,
100 rollout steps, group_size 8, rollout_batch 256 (off-policy uses train_batch 8).

## Files
- `summary_table.md` / `summary_table.csv` — final-step metrics for every run
- `onpolicy_variants.png` — GRPO vs Dr_GRPO / GRPO_constant / MaxRL / RFT
- `onpolicy_lr_sweep.png` — learning-rate sweep (3e-6, 1e-5, 3e-5)
- `onpolicy_prompt.png` — prompt ablation (question_only, r1_zero, three_shot)
- `offpolicy.png` — naive vs noclip / clip / gspo
- `combined_val_reward.png` — val_reward of every experiment on one axis

## Takeaways
- **Variants**: Dr_GRPO matches the GRPO baseline; the loss-normalization /
  baseline variants (GRPO_constant, MaxRL, RFT) all sit slightly below it.
  RFT is weakest, consistent with it being the most off-policy-flavored update.
- **Learning rate**: 1e-5 is the sweet spot. 3e-5 spikes early (best 0.34) then
  collapses — format_reward crashes to 0.11 and response length blows up to 512
  (the run stops at step 80). 3e-6 is simply too slow to learn in 100 steps.
- **Prompt**: the 3-shot r1_zero prompt is the best overall (0.514). question_only
  fails completely — the model never produces the required `</answer>` format,
  so format_reward and val_reward stay at 0 and responses run to max length.
- **Off-policy**: with train_batch 8 (single epoch), the importance-reweighting
  variants are competitive; gspo and noclip edge out naive, while token-level
  clip is the weakest here (lower format_reward). naive has a high clip_fraction
  signal but still trains fine at this small off-policy gap.
